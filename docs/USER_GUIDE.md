题目列表的「创建者」显示最初新建、复制或导入这道题目的用户，不随负责人或成员变更而改变。历史创建记录或对应用户缺失时显示「未知」。

### 4.2 可直接粘贴的 A+B 文稿

只复制代码框内的正文，不加入 Markdown 代码框标记。

题面：

```tex
给定两个整数 $a$ 和 $b$，请计算它们的和。

\InputFile
输入一行，包含两个整数 $a$ 和 $b$，满足 $0 \le a,b \le 10^9$。

\OutputFile
输出一个整数，表示 $a+b$。

\Note
请注意整数范围。
```

文档题解：

```tex
\section{思路}
读入两个整数，计算并输出它们的和。

\section{复杂度}
时间复杂度为 $O(1)$，额外空间复杂度为 $O(1)$。
```

Beamer：

```tex
\begin{frame}{A+B：解题思路}
\begin{itemize}
\item 读入整数 $a$ 和 $b$。
\item 使用足够范围的整数类型计算 $a+b$。
\item 输出结果，时间复杂度为 $O(1)$。
\end{itemize}
\end{frame}
```

题面样例从正式数据绑定：在测试数据中勾选「题面样例」，保存输入和答案后，在题面「引用样例的具体数据版本」中选择它，再保存。数据更新后已有绑定仍指向旧版本，需显式重新选择。

绑定的样例会自动放在正文末尾的 `\Note` / `\Notes` 提示之前，顺序为题目描述 → 输入 → 输出 → 样例 → 提示。正文没有提示章节时，样例放在正文最后；无需手动复制样例到正文。

多个短样例会合在同一张左右双列表格中，共用输入/输出表头，每组样例占一行并以横线分隔；跨页时重复表头。样例的输入或输出有一行超出左右栏宽度时，该组会自动改为上下排列（输入在上、输出在下），前后连续的短样例各自合表，顺序不变。两种布局的表格整体居中，数据内容左对齐。上下排列后仍超过整行宽度的文本会自动折行，仅改变 PDF 的显示，下载的数据内容不变。使用已有模板也会生效，点击「构建 PDF」生成新版即可。

图片通过「图片资源 → 上传图片」上传 PNG/JPEG，再「插入当前稿件」。不要填磁盘路径；正文不要加入 `\documentclass`、`\usepackage`、`\begin{document}` 或文件读取命令，样式需求交管理员模板处理。

### 4.3 构建和预览

点击当前稿件「构建 PDF」，等待 `QUEUED → RUNNING → SUCCEEDED`，查看「PDF 预览」；失败切到「构建日志」。三类稿件各自构建。

所有 PDF 预览均按页连续向下排列，在预览区域上下滚动即可查看全文；顶部显示总页数，保留适应宽度、缩放和下载，不需要点击上一页/下一页。题面、文档题解、Beamer、模板中心和比赛/任务详情使用同一预览方式。

新版题面模板在单独出题时只显示当前稿件题名，不加 `Problem A`；比赛题册按配置的题号显示 `Problem A. 题名`、`Problem B. 题名`，目录使用相同格式（CWNU v4 / 简洁蓝色 v3 起）。题面正文的章节标题和文档题解的题名、章节标题均左对齐；Beamer 版式保持原样。

正文、样例或模板绑定改变后，旧 PDF 仍可查看，但会提示历史/过期；重新点击「构建 PDF」才能检查新版本。「重试此任务」沿用原任务快照。私有预览和下载足以完成普通自测，公开链接的含义见第 8 节。

### 4.4 一键套用交互题正文格式

在「题面与双题解出版 → 题面」点击标题/作者下方的「交互题格式」，选择并预览：

- **通用交互题结构：**包含题目描述、初始信息、询问、回答、交互注意事项和交互示例，替换其中的说明文字即可编写自己的协议。
- **多项式机器（Easy Version）完整示例：**包含完整多项式题面、`? k` / `! a0 a1 ... an`、询问次数及整数范围、C++ 刷新缓冲区代码和逐行交互示例。可勾选同时使用示例题面标题。

已有正文时可选择「替换当前正文」或「追加到末尾」；空正文直接「插入正文」。应用后是当前文稿的未保存草稿，检查并修改内容后点击「保存」，再按需要构建 PDF。排版使用当前绑定的管理员题面模板。

```tex
\Description
题目描述……

\interactor
交互协议……

\InteractionStart

\InteractionQuery
```

## 5. 从零完成 A+B 的 Judge 验收

### 5.1 判题配置

创建题目「我的测试 · A+B」，进入「程序、数据与验收 → 判题配置」，设置并保存：

| 配置 | 值 |

| Checker 模式 | token（忽略 ASCII 空白，拒绝多余 token） |

时空限制的入口就在本页：「CPU 时间限制 / ms」填写毫秒（例如 2000 为 2 秒、2500 为 2.5 秒），「内存限制 / MiB」填写内存数值。点击「保存判题配置」后，回到「题面与双题解出版」点击「构建 PDF」，新题头会使用已保存的限制和输入输出设置。修改限制不会更新已经生成的 PDF；旧题面会标为历史产物，需选择新的构建结果查看。修改判题限制后，相关验收报告也需要重新执行。

此练习不需要自定义 Checker 或 Interactor，保持数据组为空，不启用生成计划。

### 5.2 主标程

「程序 → 新建程序」的源码编辑器上方有「写法参考」，按所选角色和编译语言显示模板。新程序默认展开；查看已有程序时可点击「查看模板」。每个模板附带用途、输入输出或生成命令示例，以及关键接口的说明。

| 角色 | 可用示例 |
| --- | --- |
| 主标程、正确解等解法 | A+B 读写框架（C++ / C17 / Java 17 / Python 3） |
| 生成器 | 随机整数数组（C++ / Python 3）、随机排列（C++） |
| Validator、额外 Validator | 数组范围、空格、换行与文件结尾校验（C++） |
| Checker | 单个整数答案、多解构造题（C++） |
| Interactor | 一问一答（C++），并附配套交互解法（C++ / Python 3） |

选择模板只改变预览。「复制模板」复制代码；「填入编辑器」写入当前草稿，空名称会补上建议名称。已有程序或已修改的源码会先提示确认替换，取消后保留原代码；还需点击「保存程序」才会更新服务端版本。切换角色不会替换源码，模板也不会替你更改编译配置、题目判题方式或启用工具。

这些示例用于说明接口，范围、算法和判定条件需按题意调整。错误解、预期超时解和暴力解提供读写框架及用途提示，需要自行实现对应算法。C++ 模板兼容 C++17 / C++20 / C++23；C / Java 生成器仍可自行编写，当前未附带对应生成器模板。Validator、Checker、Interactor 使用 C++。随机种子、`inf` / `ouf` / `ans` 和交互刷新方式也会在对应角色的提示中说明。

在「程序」点击「新建程序」，名称「A+B 主标程」，角色「主标程」，profile `GNU C++17`，启用，预期 `AC`：

```cpp
#include <iostream>
using namespace std;
int main() {
    long long a, b;
    cin >> a >> b;
    cout << a + b << '\n';
    return 0;
}
```

点击「保存程序」，再「编译当前源码」检查日志，返回「程序」继续添加工具。

### 5.3 Validator

新建名称「A+B 输入校验」，角色 **Validator**，profile `GNU C++17`，启用：

```cpp
#include "testlib.h"
int main(int argc, char* argv[]) {
    registerValidation(argc, argv);
    inf.readInt(0, 1000000000, "a");
    inf.readSpace();
    inf.readInt(0, 1000000000, "b");
    inf.readEoln();
    inf.readEof();
}
```

保存。`testlib.h` 由平台工具链提供。这个校验器要求两个数间恰好一个空格，并以换行结束；填写输入数据时在数字后按一次 Enter。

### 5.4 错误解

新建名称「故意做减法」，角色「错误解」，profile `GNU C++17`，启用，预期判定选 `WA`：

```cpp
#include <iostream>
using namespace std;
int main() {
    long long a, b;
    cin >> a >> b;
    cout << a - b << '\n';
    return 0;
}
```

保存。错误解用于检查数据能否发现已知错误；符合预期的 WA 可以使整体验收通过。编译失败不能当作有效 WA。

### 5.5 正式数据

进入「测试数据 / 生成计划 → 添加数据」，逐条填写，勾选「保存指定答案（也可由主标程生成）」后填写答案，再「保存版本」。输入与答案末尾都加换行，三条均启用：

| 编号 | 输入第一行 | 答案第一行 | 题面样例 | 分组标签 |
| --- | --- | --- | --- | --- |
| 1 | `1 2` | `3` | 是 | `main` |
| 2 | `0 0` | `0` | 否 | `main` |
| 3 | `1000000000 1000000000` | `2000000000` | 否 | `main` |

`main` 只是整理标签，不自动建立计分组。答案可直接填写，也可先保存无答案数据，再由主标程生成。

批量上传使用「导入 ZIP」，成员形式为 `1.in` / `1.ans` 或 `tests/1.in` / `tests/1.ans`。答案可缺省；同编号冲突整批拒绝。单个输入/答案最大 64 MB（64,000,000 字节）；测试 ZIP 最多 100 组、压缩输入 128 MB、展开内容 256 MB。

生成错误时，在「测试数据 / 生成计划」中点击对应行的「删除」；也可勾选多行后点击「删除所选」，表头复选框可以全选本题全部正式数据。核对确认窗口中的编号后提交，输入和答案会一起从当前数据列表移除。删除后编号可重新使用：例如删除 #1～#9，再将生成计划的起始编号设为 1，修改命令、执行并收集新数据即可。遇到版本冲突时整批不删除，点击「刷新数据」后重新选择。

删除只调整当前正式数据。历史任务、冻结修订和题面已绑定的样例版本会保留；要替换题面样例，在题面的样例选择框中取消旧引用或选择新版本后保存。评分组引用已删除的数据时会提示，需要在「数据组与评分」移除旧成员、选择新数据并保存；空组需补充成员或移除整组。生成计划不会随数据删除，请按需要修改或停用；修改当前数据后重新进行相关校验和验收。

### 5.6 自测、答案和验收

可先在「工具自测 → 添加自测」为上述 Validator 保存合法输入 `1 2` 加换行，预期 `ACCEPT`；再保存非法输入 `-1 2` 加换行，预期 `REJECT`。点击「运行自测」核对结果。非法输入放在自测里，不加入启用正式数据。

然后进入「验收与日志」：

1. 点击「校验输入」，确认启用正式数据通过 Validator。
2. 如需生成/更新答案，点击「生成答案」。完成后打开报告「输入与答案」，选择数据并点击「收集所选输入 / 答案到正式数据」。收集产生新正式版本；仅生成任务不会改写正式数据。
3. 回题面选择 #1 当前含答案的样例版本，保存三份文稿，按需构建 PDF。
4. 确认程序、判题配置、数据已保存，点击「验收当前版本」。
5. 检查「验收矩阵」：主标程全部 AC；减法错误解在 #1、#3 为 WA，在 #2 可以 AC。
6. 检查总体验收通过。**`SUCCEEDED` 仅表示任务执行完成，还要看验收结论。**

修改程序、数据或判题依赖后旧报告可能过期，需点击「验收当前版本」。只改文稿通常不使 Judge 报告失效，但会影响文稿构建及修订与冻结。

## 6. 整题修订与冻结

各编辑器的「保存」保存自身版本；整题修订把所有已保存内容固定成可审阅清单。

1. 完成验收，检查各分区没有未保存编辑，进入「组织、修订与协作 → 修订与冻结」。
2. 确认「当前判题依赖已验收」，填写修订说明，如「首次手测完整版本」。
3. 点击「保存当前工作副本为修订」，选中新修订，检查与当前工作副本的差异。
4. 负责人直接点击「检查验收并冻结」，得到「已冻结」状态。

无需提交、批准或退回步骤。团队仍可在固定修订上评论，审题成员不承担审批操作。

冻结需要工作副本与修订一致、匹配的成功验收，以及至少一种启用且非空题面。修改依赖后要保存新修订，不能冻结已与工作副本不同的修订。工作副本继续编辑不会改变历史冻结清单。

「恢复为新修订」追加新的工作版本并保留历史，恢复后重新验收。「归档」保留历史与产物，列表默认隐藏；勾选「包含已归档」会立即刷新列表并回到最新一页，无需再点「搜索」，取消勾选会重新隐藏归档题目。已有搜索条件与归档筛选共同生效。

## 7. 编排比赛和生成资料

1. 在「比赛」创建比赛，进入「比赛编排」，填写名称、署名、语言、场次、页眉日期和封面日期。
2. 分别选择题面、文档题解和 Beamer 的比赛模板；下拉框按语言和比赛支持情况筛选。CWNU 题面用于新比赛时选支持当前整场编排的 v2。
3. 选择有权访问的源题，点击「加入比赛」，无需先选择冻结修订。初次可只加入自己的 A+B。已有比赛也自动跟随源题最新保存的内容，无需移出重加。
4. 设置题号，用「上移/下移」控制题册顺序，「Beamer 讲解顺序」独立控制讲解次序，重排仍保留原题号。
5. 点击「保存编排」，检查最新题目内容的完整性。题目名称、文稿、样例绑定、判题设置、程序和数据等保存后自动同步；打开的比赛页约每 10 秒或返回窗口时更新信息，保留未保存的编排。
6. 在「冻结与资料」默认选择「最新题目内容（自动同步）」，分别生成三类资料，或「同时生成两种题解」。每次生成自动固定当次内容，负责人也可先点击「检查完整性并冻结」。明确选择历史冻结版本时，生成的仍是该次历史内容。
7. 选择子任务查看「PDF 预览」「真实编译日志」「固定来源」。组合任务部分失败时可只重试失败子任务。

固定比赛资料要求选定语言的题面完整、当前判题依赖有成功验收，两种题解按需构建。缺稿时回源题补齐并保存即可，无需再冻结源题或更新比赛引用；也可勾选「显式选择题目子集」只构建完整材料。子集 PDF 的来源会明确标示。修改程序、数据或限制后仍需重新验收；只改文稿可复用匹配的验收。历史冻结清单、已生成 PDF、已导出题包和已发布链接保持原内容；重新生成可取得最新内容，过期资料不能再次作为当前资料发布。

## 8. 题包导出、发布与导入

### 8.1 私有导出

在题目「组织、修订与协作 → 题包与发布」顶部选择 Hydro 和「当前已保存的内容」，点击「导出 Hydro 题目包」，阅读转换报告后下载。包名和顶层目录为「题目名称_导出时间」（北京时间），内含 `statement.md`、`题解.md` 和 `tests/`。题面与文档题解使用工作区当前选择的语言，将 LaTeX 标题、列表、强调、表格等转成 Markdown，公式保留 `$…$` / `$$…$$`；样例按题面绑定版本写入代码块，引用图片另放 `assets/`。缺少或停用文档题解时文件会明确注明；不能转换的结构保留代码并在报告中提示核对。

Hydro 的 `tests/` 按原编号保存普通题的 `*.in` / `*.ans`、所需 `checker.cc` / `interactor.cc`、`config.yaml` 和工具依赖。交互题只放隐藏测试 `*.in`，不导出或补空 `.ans`，展示样例仍在 `statement.md`。解压后分别使用 Markdown 题面和题解，并在 Hydro 测试数据管理中上传 `tests/` 内的文件，或仅将该目录内容另打成 ZIP 上传。

题面按“题目描述 → 输入格式 → 输出格式 → 样例代码块 → 样例解释”导出。样例的代码块标记为 `input1` / `output1`，多组从 1 开始连续编号，不额外显示“样例输入／输出”标题；原有其他小节仍保留。调整导出格式后请重新生成题目包，历史下载不会改写。

NovaJudge 有两个入口。选择 **NovaJudge 题目包**，再点击「导出 NovaJudge 题目包」，可下载包含 `problem_1_题目名称/problem.json`、`data/` 和题面引用 `assets/` 的完整 ZIP；在 NovaJudge 管理后台的「导入题目」上传整个包。题面使用当前语言，自动转换为分节、展示样例和提示，并写入题目时空限制。导入时分配新题号并重写图片路径，包内的 1 不是目标题号。这个包不包含题解或参考解。

普通题默认使用 NovaJudge 传统格式 `default`；其比较会统一换行、忽略行末空格和全文首尾空白，与平台 EXACT / TOKENS 规则不同。若要保持本地判定，选择 **保留本地比较规则（普通题转为 SPJ）**。自定义 Checker 和浮点比较自动导出为 `spj`，交互题自动导出为 `interactive`，无需手动修改 JSON。交互判题数据只有隐藏输入，配置答案为 `/dev/null`，展示样例的输入输出仍保留在题面中。

已有目标题目、只需更新数据时，仍可选择 **NovaJudge 测试数据 ZIP**，`.cpp` 工具、数据和 `problem.yml` 位于 ZIP 根目录，上传到对应题目的测试数据管理。两站均可选择已有固定修订，无需先冻结；历史下载内容不变，旧包需重新导出才能得到新增格式。

Hydro 交互题的 `tests/config.yaml` 使用 `interactor: { file: interactor.cc, lang: auto }`，测试点放在 `subtasks` 下总分 100、编号 1 的 `sum` 组中，每个测试点指定 `input: 编号.in` 和 `output: /dev/null`。时空限制取当前导出版本的题目配置，测试点按实际非样例编号升序列出，所有引用相对 tests/。

普通题应先生成并收集答案；只导出启用数据，交互判题数据排除仅用于展示的样例。不执行生成计划，专用导出均不含标程。NovaJudge 完整题目包携带时空限制；仅上传测试数据 ZIP 时，仍需在题目设置填写报告中的时间、内存限制。自定义工具的 C++ 标准、交互器参数和输出限制按报告核对；若显示「待处理」，须先调整相关判题设置再使用。导出保存在私有历史中，后续编辑不会改变已下载包。

进入题目或比赛「题包与发布」，选择来源、用途、格式，点击「生成题包」，阅读报告后「下载私有题包」。单题选择固定修订；比赛默认「最新题目内容（自动同步）」，由比赛负责人或编辑生成，也可选择历史冻结版本。

| 用途 | 内容 |
| --- | --- |
| 题面 | 正文及引用样例、图片，不含私有正式数据和题解 |
| 文档题解 / Beamer 题解 | 分别交付对应稿件 |
| 正式数据与判题工具 | 数据、答案及判题工具，不含参考解源码 |
| 参考解源码 | 启用主标程和正确解 |
| 完整题目包 `FULL` | 原生格式的完整源码交接与再导入 |

第一次往返测试选择 **ProblemForge 原生 v1 + 完整题目包**。未冻结题目修订可先私有导出，正式发布需要当前工作副本对应的冻结版本。

### 8.2 发布链接

私有下载按当前成员权限检查。「公开发布」生成无需登录的链接，每类 PDF/题包分别发布和撤回，发布题面不会自动发布题解。

当前服务仅监听本机回环，材料发布不会自动把网站部署到公网。普通自测用私有预览/下载即可；测试发布时使用自己的测试材料，在隐私窗口检查，再「撤回」验证后续下载不可用。已下载副本无法追回。

### 8.3 导入

在题目列表点击「导入题包」，选择格式与 ZIP，点击「检查兼容性」。先读报告，再确认「创建私有题目」；历史记录可在「我的历史检查」重开。

原生只有 `FULL` 可恢复为工作副本。新题归导入者私有，需重新验收和冻结，不继承成员、发布和旧成功任务。模板版本不匹配时重选本机已发布模板；profile 不匹配时按报告处理映射。

Polygon 为离线明确子集，`BLOCKED` 项必须处理。真实外部样包验收目前暂缓，不把原生往返当成完整 Polygon 兼容。字段和大小限制见 [PACKAGES.md](PACKAGES.md)。

## 9. 进阶判题

### 9.1 生成计划

先在「程序」保存角色为「生成器」且已启用的程序，再进入「测试数据 / 生成计划 → 添加计划」。生成器每运行一次，将一组测试输入写到标准输出；计划负责按参数和种子重复调用它，不负责生成答案。

生成器每次最多输出 64 MB，超过时报告 OLE（输出超限）。这与「判题配置」中的解法输出限制相互独立；生成器输出的是测试输入，主标程和其他解法才按题目设置限制答案输出。平台从旧 8 MB 限制升级后，重新点击「生成答案」或「执行生成计划」创建当前版本任务；「重试原快照」固定旧策略，不能用于放宽限制。

新计划默认使用「逐行命令 · 每行一组」。直接在多行文本框粘贴：

```text
gen 1 10001
gen 2 10002
gen 3 10003
gen 4 10004
gen 5 10005
gen 6 10006
gen 7 10007
gen 8 10008
gen 9 10009
```

这会保存为一个含 9 行命令的计划，各行的 `n` 和种子分别按原样使用。首项 `gen` 必须与本题「程序」里生成器的名称相同，末项是整数种子，中间各项是 argv 参数；一个计划也能按行使用不同的生成器。无需再选生成器或填写生成数量，名称留空时自动命名。空行忽略，含空格的程序名/参数可以用单引号或双引号包裹；错误会标出原始行号。

文本框下方实时预览每一组的生成器、参数、种子和编号。新计划的起始编号默认接在已有数据及已启用计划范围之后，也可手动修改；编号重叠会提示。已有 #1～#10 时，这 9 组默认使用 #11～#19，不覆盖原数据。每个计划最多 100 行，每行最多 32 个普通参数，种子最多 18 位数字；这里只填写生成器调用，不支持 Shell 循环、管道或重定向。

如需所有组使用相同参数、仅种子递增，可切换「固定参数 · 种子递增」。以接收 `gen <n> <seed>` 的生成器为例：

| 字段 | 示例 | 含义 |
| --- | --- | --- |
| 生成器 | 已保存的 `gen` | 选择本题的生成器程序 |
| argv | `["1"]` | 传给程序的固定参数，此处 `n=1`；填写 JSON 字符串数组，不含程序名或系统追加的种子 |
| 起始种子 | `10001` | 每组加 1，同时作为最后一个参数及 `PF_SEED` 环境变量传入 |
| 数量 | `10` | 运行 10 次，生成 10 组输入；不会自动改变 argv 中的 `n` |
| 起始编号 | `1` | 生成的数据编号为 #1～#10，需避开已有正式数据和其他启用计划的范围 |
| 分组 | `main` | 数据标签；评分组仍需在「数据组与评分」另行保存 |

这种固定参数配置相当于依次调用 `gen 1 10001` 到 `gen 1 10010`。如果程序直接输出 `n seed`，各组内容就是 `1 10001\n` 到 `1 10010\n`。已有旧计划保留这种模式；也可在编辑时切换为逐行命令，系统会将原配置展开到文本框，再逐行修改。

1. 保存计划，点击「执行生成计划」。它会执行本题所有已启用的计划。每个计划的第一组还会重复运行一次，用于检查相同参数和种子的输出是否一致。
2. 成功后进入该任务的「输入与答案」，下载核对输入，点击「选择可收集数据」及「收集所选输入 / 答案到正式数据」。生成任务的 `NOT_RUN` 表示尚未执行 Validator，生成阶段没有答案是正常的。
3. 收集完成后，正式数据保持启用。计划可以继续启用：再次生成输入、校验、生成答案和完整验收时，生成结果与已启用正式数据或本任务先前生成的输入完全相同，会自动跳过重复项，报告只汇总提示跳过数量；生成答案仍会正常处理已有正式数据。无需为了避免重复而手动停用计划；不再需要运行的计划也可取消「启用」并保存。
4. 普通批处理题接着执行校验、生成答案、收集答案及完整验收。交互题先配置双向交互和 Interactor，再运行对应任务；不能把批处理模式产生的输出当成交互验收成功。

收集按钮只对成功且未过期的任务可用。去重依据原始输入字节的 SHA-256；编号相同但输入内容不同仍会保留并提示冲突，需调整计划编号后重新执行，收集不会覆盖已有正式数据。单独生成输入时只列出新增输入，全部重复也可以成功完成；已经收集的输入无需再次收集。生成答案后仍需显式收集答案到正式数据。使用固定评分组前，先收集输入并停用对应计划，再显式保存组成员。

### 9.2 数据组和部分分

在「数据组与评分」添加组，或「按现有标签建立草稿」，填写标识、满分、计分方式、成员及依赖，再「保存数据组」。启用正式数据必须恰好被分配一次。

- `ALL`：全组通过才得满分。
- `WEIGHTED`：按通过数据的权重比例计算。
- 依赖：依赖组未全过，本组最终分为零，报告保留原始分和阻断原因。

修改数据后用「成员升级到当前版本」并保存。在「判题配置」选择部分分并保存，不能只填整理标签。主标程/正确解仍需全 AC、满分，其他解法可设置总分或组分预期，报告见「组分与总分」。例如 20/30/50 分三组，第二组通过一半权重，第三组依赖第二组且本身全过，得到 `20+15+0=35` 分。

### 9.3 对拍与反例

选择生成器、参考解、另一个被测解、Checker、argv、种子、迭代上限、总预算和停止策略，保存后运行。首次使用少量迭代和明确预算。

反例可下载输入/参考输出/被测输出、「复现保存输入」，或填写新编号后「显式加入正式数据」。入库使相关验收过期，应重新验收。预算内未发现反例不等于证明正确。

### 9.4 Checker、文件 I/O 和交互

自定义判题先保存启用的 testlib Checker，在配置中选择 `CUSTOM`，用工具自测检查接受/拒绝语义。文件 I/O 配置指定输入/输出文件名，程序相应读写，stdout/stderr 仍单独保留。

交互题保存启用的 Interactor，选择双向交互，设置判定方式、资源和空闲限制，注意 flush、EOF，在报告检查双方执行结果与通信记录。详细协议见 [JUDGE.md](JUDGE.md)。作者程序和 TeX 只由独立 Linux 沙箱执行，不可用时失败，不在 Windows 宿主机回退。

使用 testlib 时，`inf` 读取隐藏测试输入，`ouf` 读取选手输出，向选手发消息使用 `cout << ... << endl`；`tout` 写入 `interaction-output` 文件，不连接选手的标准输入。由 `quitf(_ok/_wa/...)` 直接判定的程序选择「Interactor 直接判定」。仅保存一个角色为 Interactor 的程序不会自动把判题配置从「批处理」切换为「双向交互」。

保存「双向交互」后，测试数据中勾选「样例」的条目只作为交互示例展示，不执行 Validator、生成答案或验收，也不进入数据组和导出的判题数据文件；Hydro 题包的 statement.md 仍保留绑定样例。示例输出请手工填写或上传，原题面绑定继续保留；真正交给 Interactor 的隐藏输入不要勾选「样例」。样例生成计划同样不进入校验、答案和验收，仍可单独执行生成输入。只有样例而没有隐藏测试时，系统会在提交前提示补充非样例数据。普通批处理题的样例仍照常测试。

旧数据组若包含交互样例，在「数据组」中移除不参与判题的成员并保存。旧交互任务保留原记录，请从工作区重新提交当前任务以应用此规则，不要重试旧快照。仅修改展示样例内容不会使判题验收失效。

交互任务的报告使用「输入与交互记录」标签，每组分别提供隐藏输入、Interactor 输出、主标程输出及有界通信记录。直接判定模式下，「Interactor 附加输出」来自 `tout`：若程序没有写入，它就是 0 字节，不能据此判断主标程没有输出或验收失败。实际询问和最终回答在「主标程输出」中，双方消息在「通信记录 · JSONL」中；是否通过看验收矩阵和 Interactor 判定。若采用「Interactor 输出交 Checker」，则 `tout` 是比较用输出，按本题 Checker 协议检查内容。收集会保存该文件到正式数据的答案字段，不会把主标程的通信内容自动转换成静态标准答案。

## 10. 历史任务、取消和重试

「任务中心」按 TeX/Judge、状态、用途、题目/比赛 ID 和起止时间筛选。ID 是对象地址最后一段。默认显示自己发起且仍有权限的任务；填写对象 ID 可查询该对象有权查看的团队历史。

「更早任务」向历史翻页，「上一页」返回本次浏览上一页，「最新一页」重开查询。地址保存筛选、当前页和所选任务；实时新任务提示不会替换当前报告/PDF。工作区仅保留最近 50 条摘要，更早记录用「全部 TeX 历史 / 全部 Judge 历史」。

| 状态 | 含义 |
| --- | --- |
| `QUEUED` / `RUNNING` | 等待/执行，可取消；持续堆积时查看运行管理与 Worker 日志 |
| `SUCCEEDED` | 执行完成，Judge 还需看验收是否通过 |
| `FAILED` | 检查错误码、编译/执行日志，区分源码、工具、数据和基础设施问题 |
| `CANCELED` | 已取消，保留已完成证据，可按需重试 |
| 历史 / 过期 | 原结果可读，不能充当当前依赖的有效验收或发布依据 |

「重试原快照」执行当时的版本。更改源码/数据/配置后应提交当前版本新任务。默认每用户最多同时有 3 个 Judge 任务、6 个 TeX 构建排队或运行，不要连续重复点击。更多检索说明见 [HISTORY.md](HISTORY.md)。

## 11. 保存冲突与草稿恢复

文稿、程序、比赛和模板显示保存中、未保存、已保存版本及失败提示。请求发出后继续输入的改动仍为未保存状态。浏览器标签页记住语言、稿件、功能区和程序选择，返回列表保留搜索条件。

**导航记忆不是正文备份。** 刷新/关闭前先保存。遇到失败、409 冲突或登录失效：

1. 保持编辑器，点击「下载本地草稿」。
2. 查看 JSON，下载或复制保存到本地；下载受限时使用「复制」，也可在文本框全选复制。
3. 取回草稿后再登录或重新载入服务器版本。
4. 对照内容和基准版本，逐项粘贴合并后保存。

没有草稿 JSON 自动导入/覆盖按钮。草稿含私有正文/源码，需自行保管；弹窗内容只在浏览器内存里，关窗前实际保存为文件。

冲突保留、复制 JSON 和导航恢复已做浏览器验证。内嵌浏览器的 Blob 下载、401 编辑保留及全部原生离开弹窗组合尚未全部完成浏览器实测，具体限制见 PROGRESS。

## 12. 管理员日常操作

### 12.1 账号

「用户管理」区分独立超级管理员和协会用户，调整系统角色、启停本系统账号、撤销会话。「账户设置」查看会话、退出其他设备或所有设备。角色/启停变更立即撤销对应本地会话；最后一个可登录的独立超级管理员不能被停用或降权。

协会用户的注册、名称、邮箱和密码在官网管理，资料在下次登录时同步；官网改密不会主动注销本系统的存量会话，必要时在本系统撤销。独立超级管理员在本系统「账户设置」修改本地密码，改密撤销所有会话。普通本地用户创建和一次性密码重置入口保持关闭，配置见 [ACCOUNTS.md](ACCOUNTS.md)。

### 12.2 模板与编译 profile

模板中心现在使用文件工作区。点击「模板目录」选择模板和版本；已发布版本先点「创建草稿并编辑」。左侧展开文件夹，点击文件即可打开源码编辑标签或图片预览。

替换 Logo：选中原图片 →「替换图片」→ 选择同格式 PNG / JPG → 确认替换 →「保存草稿」→「验证样稿」→ 检查 PDF → 发布。文件路径保持原样，原来的 TeX 引用可继续使用。新增图片或源码可用「上传文件」多选，或直接拖入工作区，在上传窗口填写目标文件夹；重名项会标明替换。图片单张最多 1.5MB，文本为 UTF-8，整个模板最多 40 个文件 / 10MB。

工具栏还可新建、重命名、删除、下载或还原文件；重命名和删除后需同步修改源码引用。标签页上的圆点和文件树 A / M 表示未保存，关闭标签不会删除文件或丢弃修改。工作区内 Ctrl / ⌘ + S 保存整个草稿。「PDF / 日志」展开构建结果，「样式设置」展开字体、页边距等配置。

管理员在模板中心可以使用：

- **重命名**：点击左侧模板名称旁的「重命名」，填写新名称并保存。整套模板立即显示新名称，已发布版本也可操作；既有版本内容、绑定和历史 PDF 保留。
- **复制为新模板**：先选中想作为基础的具体版本，再点击「复制为新模板」，输入名称后创建独立的 v1 草稿。全部文件、图片和样式配置一并复制，之后编辑副本不会影响原模板。有未保存修改时需先保存草稿。
- **复制为新版本**：在同一套模板下创建下一版，用于继续迭代原模板。

新建或复制的草稿都需「保存草稿」→「验证样稿」→ 检查「真实 PDF 预览」及日志 →「确认预览并发布」。副本不继承原验证和发布状态；已发布版本的源码不可原地修改。

发布新版不会自动重绑定现有题目/比赛，使用者显式换绑再构建。归档停止新选择，撤回阻止新构建。协议见 [TEMPLATES.md](TEMPLATES.md)。

「编译配置」已有 C17、C++17、C++20、C++23、Java（JDK 17）和 Python 3，管理员可以维护启停、编译警告及资源限制；C / C++ 另有 O0 / O2。程序中选择对应 profile 即可，任务固定具体版本，配置变化后需重新核对验收有效性。C++23 基于 GCC 12，部分较新的特性尚未实现，详情见 [Judge 文档](JUDGE.md)。

Java 程序写在 `public class Main` 中，入口为 `public static void main(String[] args)`，不要添加 `package` 声明；内部类和同文件的其他非 public 类会一并编译打包。新建程序切换语言时，尚未修改的初始代码会换成对应样板，已有代码不会自动覆盖。C、Java 和 Python 可作为解法或生成器，testlib 工具仍选择 C++。Java 的 JVM 开销同样计入题目时间和内存限制。

| 旧示例打不开、题目和比赛列表为空 | 2026-10-02 已按要求清空，完成登录配置后直接新建；不要重新初始化测试数据 |
| 新用户题目列表为空 | 需要负责人授权，或自己创建私有题目 |
| 模板列表为空 | 检查稿件类型、语言及管理员发布状态 |
| 保存后 PDF 没变 | 保存和构建分开；创建新构建并选择新任务 |
| TeX 拒绝命令 | 按位置提示修正正文，导言、宏包和样式交模板处理 |
| Validator 拒绝 A+B | 检查范围、单空格和行末换行 |

| 生成/答案不能收集 | 检查依赖是否过期，按当前配置新建任务 |

| 比赛找不到源题 | 加入比赛需要源题访问权限，不要求已有冻结修订 |
